# ADR-001: Runner de migraciones compilado con `pg`

## Contexto

La imagen productiva debe inicializar y actualizar PostgreSQL antes de arrancar. El comando existente usa `psql`, que no está instalado en `node:20-alpine`, no mantiene un historial y no incluye todas las migraciones.

## Opciones consideradas

1. Instalar `psql` en la imagen — simple para ejecutar archivos SQL, pero aumenta la imagen y no resuelve por sí solo ledger, locks ni preflight.
2. Añadir un framework de migraciones — ofrece historial, pero introduce una dependencia y una reorganización mayor para tres migraciones existentes.
3. Implementar un runner compilado con `pg` — reutiliza la dependencia actual y permite ledger, advisory lock y validaciones específicas.

## Decisión

Usar un runner TypeScript dentro de `src/scripts/`, compilado junto con el backend y basado en `pg`.

## Consecuencias

- La imagen no necesita herramientas PostgreSQL adicionales.
- El proyecto mantiene la responsabilidad de probar el runner y sus transacciones.
- Las migraciones futuras deberán agregarse explícitamente a la lista ordenada del runner.
- Una base existente sin ledger se detendrá para revisión manual en vez de arriesgar datos.
